# Marketplace integrations

Swiggy and Zomato are **not connected** in this deployment. The repository has provider status reporting and an adapter boundary, but no merchant/POS integration credentials, webhook secrets, sandbox access, or reviewed partner contract were provided. The setup guide intentionally does not prescribe private dashboard automation or undocumented endpoints.

The official [Zomato POS integration overview](https://www.zomato.com/developer/integration/docs/overview/) documents menu, outlet, and order-management APIs and says POS vendors must configure webhooks for order updates. Its [prerequisites](https://www.zomato.com/developer/integration/docs/getting-started/prerequisites/) currently list a minimum of 50 restaurants or 10,000 monthly orders, critical feature parity, a 24/7 on-call channel, and 99.999% uptime; final eligibility is decided by Zomato. This application has not met or obtained acceptance for those requirements, so its Zomato adapter remains disconnected.

Swiggy now has an official [Builders Club API/MCP program](https://mcp.swiggy.com/builders/docs/start/developer/) that describes Food/Instamart/Dineout commerce tools, with production access review and staging onboarding in its [production-access process](https://mcp.swiggy.com/builders/access/). That is a user commerce API offering; the material reviewed does not establish a restaurant-partner POS feed for ingesting a merchant's Swiggy orders into a third-party POS. Do not treat those consumer commerce APIs as that feed. Seek the applicable merchant/POS partner contract directly with Swiggy before connecting restaurant order ingestion.

Before enabling either provider, obtain acceptance and written partner access for this POS product and its restaurant tenants, plus official API/webhook documentation for the merchant. Implement the provider-specific signature verifier, payload validation, event dedupe, order upsert using `(restaurantId, source, externalOrderId)`, status transition allowlist, retries/checkpoints, and connection health endpoint. Verify inbound signing requirements and replay windows from that provider's official contract. External order state writes must remain disabled until the partner confirms the operation is supported.

The admin integration panel reports both marketplaces as `NOT_CONFIGURED` and provides manual order entry. Do not copy marketplace payments into Svaadya online checkout. After integration, preserve provider order ID and settlement metadata and reconcile delayed/duplicate webhooks in a sandbox before production. No Swiggy/Zomato sandbox verification has been performed.
